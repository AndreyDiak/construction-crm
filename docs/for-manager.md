# Как устроена система (для руководителя)

Коротко: это внутренняя CRM для стройки. Постановщик ведёт объекты и задачи, исполнители выполняют только свои задачи. Права проверяются не только в интерфейсе, но и на сервере — обойти кнопки нельзя.

## Кто что делает

**Постановщик** создаёт объекты (адреса строек), ставит задачи, назначает исполнителей, принимает работу или возвращает на доработку с комментарием.

**Исполнитель** видит только свои задачи и только те объекты, где у него есть активная задача. Он может взять задачу в работу и отправить на проверку. Принять работу или вернуть её себе сам он не может.

## Как движется задача

1. **Новая** — постановщик создал и назначил.
2. **В работе** — исполнитель начал.
3. **На проверке** — исполнитель отправил результат.
4. Дальше постановщик либо **принимает**, либо возвращает **на доработку** (нужен комментарий).
5. С доработки исполнитель снова уходит в работу и потом снова на проверку.

Каждый переход сохраняется в истории: кто, когда, из какого статуса в какой, и комментарий при возврате.

## Как защищены данные

- Вход только по выданным учёткам. Самостоятельная регистрация отключена.
- Роль задаётся администратором базы. Пользователь не может сделать себя постановщиком.
- Правила доступа живут в базе данных. Даже если кто-то подделает запрос в обход ui, сервер отклонит запрещённое действие.
- Статус задачи нельзя «просто переписать». Разрешены только правильные переходы через специальную серверную операцию.
- История статусов только пополняется: старые записи нельзя править или удалять из приложения.
- Удалённый объект не исчезает физически, а помечается удалённым. По его задачам дальше работать нельзя, исполнитель его больше не видит.

## Что не может сделать исполнитель

- видеть чужие задачи и объекты, где у него нет своих задач;
- создавать или менять объекты;
- создавать задачи и назначать людей;
- принимать задачу или возвращать её на доработку;
- менять свою роль;
- править или чистить историю статусов;
- обойти запреты через DevTools или прямой запрос к API — сервер всё равно проверит права.
