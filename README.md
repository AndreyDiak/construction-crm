# Construction CRM

Мини-CRM для строительной компании: объекты, задачи, исполнители, статусы и история изменений.

Стек: React 19, TypeScript (strict), Vite, Chakra UI v3, TanStack Query, React Router, React Hook Form, Zod, Supabase (PostgreSQL + Auth + RLS).

## Что умеет

- Вход по email/паролю через Supabase Auth.
- Роли `manager` и `executor`; регистрация отключена, роли выдаются только администратором БД.
- Менеджер создаёт, редактирует и мягко удаляет объекты, создаёт и назначает задачи.
- Исполнитель видит только свои активные задачи и объекты, к которым они привязаны.
- Статусы меняются только через RPC `transition_task_status`.
- История статусов пишется триггерами и доступна только для чтения.
- Возврат на доработку требует комментарий.
- Мягко удалённый объект скрывает свои задачи от исполнителя; менеджер видит исторические строки, но переходы по ним запрещены.

## Статусы и переходы

| Из | В | Кто |
|---|---|---|
| `new` | `in_progress` | назначенный executor |
| `in_progress` | `on_review` | назначенный executor |
| `needs_rework` | `in_progress` | назначенный executor |
| `on_review` | `accepted` | manager |
| `on_review` | `needs_rework` | manager, обязателен комментарий |

`accepted` — конечный статус. Прямой `UPDATE tasks SET status = ...` запрещён на уровне прав колонок и триггера.

## Быстрый старт с облачным Supabase

### 1. Создайте проект

Создайте проект на [supabase.com](https://supabase.com/dashboard). Дождитесь окончания инициализации.

### 2. Примените миграцию

**Вариант A — SQL Editor (проще):**

1. Откройте `supabase/migrations/20261104000000_init.sql`.
2. Скопируйте всё содержимое в SQL Editor проекта.
3. Выполните один раз.

**Вариант B — Supabase CLI:**

```bash
npx supabase login
npx supabase link --project-ref <project-ref>
npx supabase db push
```

### 3. Отключите регистрацию

В Dashboard: **Authentication → Providers → Email** (название раздела зависит от версии Dashboard) отключите возможность самостоятельной регистрации новых пользователей. Пользователей создавайте вручную.

### 4. Создайте тестовых пользователей

В **Authentication → Users → Add user** создайте трёх пользователей с подтверждённым email:

- менеджер;
- исполнитель №1;
- исполнитель №2.

После миграции триггер `handle_new_user` автоматически создаст профили с ролью `executor`.

Выдайте менеджеру роль через SQL Editor:

```sql
update public.profiles p
set role = 'manager'
from auth.users u
where p.id = u.id
  and u.email = 'manager@example.com';
```

Проверка:

```sql
select u.email, p.role
from auth.users u
join public.profiles p on p.id = u.id
order by u.email;
```

> Роль нельзя изменить через клиентский API: триггер и отсутствие `UPDATE`-гранта защищают `profiles.role`.

### 5. Настройте переменные окружения

```bash
copy .env.example .env.local
```

Заполните из **Project Settings → API Keys**:

```env
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

Используйте новый **publishable** key. Секретный ключ (`sb_secret_...`, ранее `service_role`) во фронтенде не используется и не должен туда попадать.

> Нельзя класть `sb_secret_...` в переменные с префиксом `VITE_`: Vite встраивает их в клиентский бандл. Если это уже произошло — удалите `dist`, замените ключ на publishable и перевыпустите секретный ключ в Dashboard.

### 6. Запустите приложение

```bash
npm install
npm run dev
```

### Security-тесты

Тесты работают против реального облачного проекта и реальных JWT, поэтому проверяют RLS, гранты и RPC, а не моки.

```bash
copy .env.test.example .env.test
```

Заполните URL, publishable key и данные трёх тестовых пользователей. Пароли и ключи не коммитьте: `.env.test` уже в `.gitignore`.

```bash
npm run test:security
```

Что проверяется:

- исполнитель видит только назначенные задачи и связанные объекты;
- менеджер видит все объекты, задачи и историю;
- прямой `UPDATE status` запрещён и менеджеру, и исполнителю;
- исполнитель не может редактировать задачи напрямую;
- исполнитель не может создавать объекты/задачи;
- `author_id` и `created_by` нельзя подделать;
- исполнителем можно назначить только пользователя с ролью `executor`;
- историю нельзя вставлять, изменять или удалять через API;
- повышение роли через `profiles` запрещено;
- разрешённые переходы работают, история пишется корректно;
- запрещённые переходы отклоняются;
- мягко удалённый объект скрывает задачи и блокирует переходы;
- анонимный пользователь не имеет доступа.

Тесты создают собственные объекты и задачи, а после завершения помечают их удалёнными. Повторный запуск безопасен.

## Модель безопасности

- RLS включён и принудителен (`FORCE ROW LEVEL SECURITY`) для всех таблиц.
- `profiles` читаются всеми авторизованными пользователями, но не изменяются через API.
- Исполнитель видит объект только при наличии активной задачи на этот объект.
- Исполнитель видит задачу только если она назначена ему, не удалена и её объект не удалён.
- История доступна менеджеру и исполнителю задачи; запись — только триггерами.
- SECURITY DEFINER-функции имеют фиксированный `search_path = public, pg_temp`.
- Клиентские гранты выданы только на необходимые колонки; `status`, `role`, `author_id`, `created_by`, `created_at` недоступны для прямой записи.
- `transition_task_status` проверяет роль, назначение, текущий статус, допустимость перехода, комментарий и активность объекта.
- Регистрация закрыта; профиль создаётся только с ролью `executor`.

## Структура

```text
src/
  app/          роутинг, провайдеры, guards, layout
  features/     auth, objects, tasks (api, hooks, forms, actions)
  entities/     карточки и типы домена
  pages/        страницы приложения
  shared/       api-клиент, типы БД, UI-компоненты, ошибки, статусы
supabase/
  migrations/   схема, RLS, триггеры, RPC
tests/
  security.test.mjs
```

## Примечания

- Типы БД лежат в `src/shared/api/database.types.ts` и соответствуют миграции. При изменении схемы обновляйте их (или генерируйте через Supabase CLI, сохраняя экспорт `UserRole`/`TaskStatus`).
- `npm run build` может предупредить о размере чанка >500 kB из-за Chakra UI. Это не ошибка; при необходимости добавьте code splitting.
